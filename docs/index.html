Graveyard
How it works Tools Install GitHub

Let failed fixes stay dead.

Graveyard records what your coding agent already tried and why it failed, in a file in your repo. The next session looks it up before trying the same thing again.

Install View on GitHub

Connects to Claude Code over MCP. Free, MIT licensed, and runs on your machine.

    These entries are made up, but the ranking and the output format match the real tool. Search to wake the ghosts, or choose a stone to read it in full and try reviving it.

    
      
    
    
    
  
    

  
    
    
    
      
    
        
    
          
    Why it exists
    
          
    Every new session falls in the same pit.
    
        
    
        
    
          
    Agents lose what they learned when their context gets compacted or a new session starts. So you pay for the same mistake again.
    
          
    
            
            
          
    
        
    
      
    
      
      
    
    
    
  
    

  
    
    
    
      
    
        
    
          
    How it works
    
          
    Your agent forgets. Your repo doesn't.
    
        
    
        
    Here's what that looks like in real tool calls, as an illustration. Nothing carries over between these two sessions except one line in a file.
    
      
    
      
    
        
    
          
    Monday
    
          
    The fix fails, and it gets written down
    
          
    Agent runs
    pip install "numpy>=2"
pytest
    
          
    Output
    ImportError: numpy.core.multiarray failed to import
    
          
    Agent calls
    record_dead_end(
  attempt="Bumped numpy to 2.x to fix the dtype warning",
  why_failed="broke torch 2.1 (ABI mismatch on import)",
  area="deps · requirements.txt",
  tags=["numpy", "torch", "dependencies"])
    
          
    Graveyard replies
    Recorded dead end #12.
    
        
    
        
    
          
    Thursday, new session
    
          
    The same warning, and a different choice
    
          
    Agent calls
    search_dead_ends(query="numpy dtype warning")
    
          
    Graveyard replies
    🪦 #12  Bumped numpy to 2.x to fix the dtype warning
   ✗ Why it failed: broke torch 2.1 (ABI mismatch on import)
   📁 Area: deps · requirements.txt
   🏷  tags: numpy, torch, dependencies
   🕐 2026-11-01 · by claude-code
    
          
    Agent says
    Bumping numpy already broke torch here, so I'll leave the version alone and fix the warning with an explicit dtype.
    
        
    
      
    
    
    
  
    

  
    
    
    
      
    Two ways in
    
      
    The agent gets four tools. You get a CLI.
    
      
      
        
    • search_dead_endsFinds matching entries, best first. Its description tells the agent to call it before attempting a fix.
      • 
        
    • record_dead_endSaves what was tried and why it failed, with the client's name as the author.
      • 
        
    • list_dead_endsShows recent entries, newest first.
      • 
        
    • revive_dead_endMarks an entry as having worked under different conditions.
      • 
      
    
      
    
        
    And for you, in the terminal
    
        
    
          
    graveyard init
    Sets up the folder and prints the CLAUDE.md snippet.
    
          
    graveyard list
    Shows recent entries, filtered by tag or area.
    
          
    graveyard add
    Asks for each field, or takes flags.
    
          
    graveyard show <id>
    Shows one entry in full.
    
          
    graveyard search <query>
    Searches by keyword.
    
          
    graveyard revive <id>
    Marks an entry as revived, keeping earlier notes.
    
          
    graveyard stats
    Shows totals, common tags, and the most haunted areas.
    
        
    
      
    
    
    
  
    

  
    
    
    
      
    
        
    Where it lives
    
        
    Just a file, in your repo.
    
      
    
      
    
        
    .graveyard/entries.jsonl
+{"id": 12, "attempt": "Bumped numpy to 2.x to fix the dtype warning", "why_failed": "broke torch 2.1 (ABI mismatch on import)", "created_at": "2026-11-01T13:28:31+00:00", "status": "dead", "area": "deps · requirements.txt", "tags": ["numpy", "torch", "dependencies"], "author": "claude-code"}
    
        
      
          
    • No accounts or servers. It runs on your machine, and the entries are plain text you can read.
      • 
          
    • Shared through git. Commit the folder and your teammates' agents get it too, or use --private to keep it to yourself.
      • 
          
    • Hard to lose. New entries are only appended. A revive changes one line through a temp file and a rename, and a line it can't read is skipped, never deleted.
      • 
        
    
        
    It has limits: search matches keywords rather than meaning, and it has only been run on macOS. Read the known limits.
    
      
    
    
    
  
    

  
    
    
    
      
    Install
    
      
    Dig in, in three steps.
    
      
      
        
    1. 
          
      Install it
      You'll need Python 3.10 or newer. Install once, then run graveyard init in each repo you want a graveyard for.
      
          
      
            
      git clone https://github.com/ryanjmahn/graveyard.git
cd graveyard
python3 -m venv .venv
.venv/bin/pip install -e .
source .venv/bin/activate
      
            
      cd /path/to/your/repo
graveyard init
      
          
      
        
      2. 
        
    2. 
          
      Connect it to Claude Code
      Run this from the folder you cloned. Register it once and each repo keeps its own graveyard. Start a new session to pick up the tools.
      
          
      
            
      claude mcp add --scope user graveyard -- "$(pwd)/.venv/bin/graveyard-mcp"
claude mcp list
      
            
      
              Only use the VS Code extension, with no claude command?
              
      C=$(ls -d ~/.vscode/extensions/anthropic.claude-code-*/ | sort -V | tail -1)resources/native-binary/claude
"$C" mcp add --scope user graveyard -- "$(pwd)/.venv/bin/graveyard-mcp"
"$C" mcp list
      
            
      
          
      
        
      3. 
        
    3. 
          
      Tell your agent to use it
      Paste this into your repo's CLAUDE.md. Without it, the agent has to think of the graveyard on its own.
      
          
      ## Graveyard (failed approaches)
- Before trying a fix or changing an area of the code, call `search_dead_ends` with relevant keywords.
- If an approach fails and you're switching to a different one, call `record_dead_end` with what you tried and why it failed.
- Don't retry anything listed as dead unless conditions have clearly changed. If you do, say why.
